# Codex 자동 기획 및 리뷰 워크플로우

작성일: 2026-05-17

기획 저장소: [코덱스 기획 창고](https://www.notion.so/363f1beebaaf804d808de2d9cf668c95)

## 목적

Codex는 제품 또는 엔지니어링 변경을 구현하기 전에 먼저 기획안을 만든다. 사용자가 매번 요청하지 않아도, 코드 작성 전에는 무엇을 만들지, 어떻게 만들지, 가능한 방법은 무엇인지, 왜 특정 방법을 선택했는지를 정리한다.

이 문서는 그 과정을 자동으로 반복하기 위한 기준이다.

## 자동 실행 기준

다음 작업을 시작하기 전에는 항상 기획 단계를 먼저 거친다.

- 새 기능, 화면, API, 데이터 모델, 권한, 배포, 운영 플로우를 추가하거나 바꾸는 작업
- 사용자 경험이나 제품 방향에 영향을 주는 작업
- 인증, Supabase RLS, Storage, 외부 API, 위치 정보, 개인정보, 신고/관리자 기능처럼 리스크가 있는 작업
- 테스트, 빌드, 배포, PR 작성 전에 의사결정 흔적이 필요한 작업

작은 문구 수정이나 단순 포맷 변경처럼 기획 문서가 과한 경우에도, 최소한 짧은 하위 태스크와 검증 방법을 먼저 적고 진행한다.

## 코드 작성 전 기획안 형식

기획안은 `docs/` 아래의 기존 문서에 이어 쓰거나, 필요하면 `docs/plans/YYYY-MM-DD-작업명.md`로 새로 만든다.

기획안에는 다음 항목을 포함한다.

1. 배경과 목표
2. 이번 작업의 범위와 제외 범위
3. 하위 태스크 목록
4. 구현 후보 방법
5. 각 방법의 장단점과 리스크
6. 선택한 방법과 선택 이유
7. 데이터, API, UI, 상태 관리, 권한 영향
8. 테스트와 검증 방법
9. 배포, 롤백, 운영 관찰 포인트
10. 리뷰어별 검토 결과와 최종 방향

## Notion 기획 창고 동기화

로컬 기획 문서를 만들거나 업데이트할 때는 Notion 기획 창고에도 같은 내용을 남긴다. 사용자가 따로 말하지 않아도 자동으로 수행한다.

기본 대상은 [코덱스 기획 창고](https://www.notion.so/363f1beebaaf804d808de2d9cf668c95)이다.

Notion에는 다음 방식으로 기록한다.

- 기획 창고 아래에 작업별 하위 페이지를 만든다.
- 하위 페이지 제목은 로컬 계획 문서 제목과 맞춘다.
- 하위 페이지에는 배경, 목표, 범위, 제외 범위, 구현 방법 후보, 선택 이유, 리뷰 결과, 테스트 계획을 적는다.
- 하위 태스크는 Notion 페이지 안에 체크리스트로 만든다.
- 각 하위 태스크에는 수정 영역, 완료 조건, 검증 방법을 적는다.
- 로컬 계획 문서에는 생성된 Notion 페이지 URL을 기록한다.
- 이미 같은 작업의 Notion 페이지가 있으면 새로 만들지 말고 기존 페이지를 업데이트한다. 업데이트 도구가 없으면 새 페이지를 만들기 전에 사용자에게 알린다.
- Notion 연결이 실패하면 구현을 시작하지 말고, 실패 이유와 로컬 계획 문서 경로를 사용자에게 알린 뒤 확인을 기다린다.

Notion 동기화가 끝나기 전에는 "계획 완료"로 보지 않는다.

## 하위 태스크 작성 규칙

하위 태스크는 구현 단위가 아니라 의사결정과 검증이 가능한 결과 단위로 쪼갠다.

각 태스크는 다음을 포함한다.

- 만들 기능 또는 바꿀 동작
- 예상 수정 영역 또는 관련 파일
- 완료 조건
- 필요한 테스트 또는 수동 검증
- 의존하는 결정이나 선행 작업

예시:

```markdown
## 하위 태스크

- 지도 빈 상태 CTA 추가
  - 수정 영역: `src/widgets/matzip-community/ui/`
  - 완료 조건: 등록된 맛집이 0개일 때 첫 등록 액션이 노출된다.
  - 검증: 모바일/데스크톱에서 빈 상태 CTA가 지도와 겹치지 않는다.

- Supabase production fallback 차단
  - 수정 영역: Supabase client 초기화와 운영 문서
  - 완료 조건: production에서 필수 환경변수가 없으면 local fallback으로 조용히 내려가지 않는다.
  - 검증: 환경변수 누락 테스트와 운영 체크리스트 업데이트
```

## 구현 방법 비교 규칙

하나의 방법만 바로 선택하지 않는다. 최소 두 가지 방법을 비교하고, 선택하지 않은 방법도 왜 제외했는지 적는다.

비교 기준은 다음 순서로 본다.

1. 사용자 경험과 제품 목표에 가장 직접적으로 맞는가
2. 현재 코드 구조와 잘 맞는가
3. 보안, 권한, 데이터 무결성 리스크가 낮은가
4. 테스트와 롤백이 쉬운가
5. 이후 확장에 필요한 만큼만 열려 있는가

## 자동 리뷰 파이프라인

기획안은 구현 전 다음 리뷰 관점으로 검토한다. 가능한 경우 gstack skill을 사용하고, 사용한 리뷰 관점과 결과를 문서에 남긴다.

### CEO 리뷰

사용 skill: `plan-ceo-review`

검토 내용:

- 이 기능이 지금 제품 단계에서 필요한가
- 목표 지표나 사용자 행동을 개선하는가
- 과한 범위나 흐릿한 문제 정의가 있는가
- 하지 말아야 할 일을 잘 제외했는가

문서에 남길 것:

- CEO 관점에서 본 핵심 우려
- 유지할 범위
- 줄이거나 미룰 범위
- 제품 방향 결정

### 디자이너 리뷰

사용 skill: `plan-design-review`

검토 내용:

- 사용자가 첫 화면에서 무엇을 해야 하는지 명확한가
- 정보 구조, 상태, 빈 화면, 오류 상태가 충분한가
- 모바일과 데스크톱 흐름이 자연스러운가
- UI가 기존 디자인 톤과 맞는가

문서에 남길 것:

- 디자이너 관점에서 본 UX 리스크
- 필요한 상태와 화면
- 유지할 인터랙션
- 디자인 방향 결정

### 개발자 리뷰

사용 skill: `plan-eng-review`

검토 내용:

- 현재 아키텍처와 데이터 흐름에 맞는가
- API, 모델, 상태 관리, 테스트 경계가 명확한가
- 에러 처리와 fallback이 안전한가
- 성능, 관찰 가능성, 롤백 계획이 충분한가

문서에 남길 것:

- 개발자 관점에서 본 기술 리스크
- 선택한 구조
- 필요한 테스트
- 구현 순서 결정

### 보안 이슈 리뷰

사용 skill: `cso` 또는 현재 작업에 맞는 보안 리뷰 skill

검토 내용:

- 인증과 권한 경계가 올바른가
- Supabase RLS, Storage policy, API route 권한이 안전한가
- 사용자 입력, 파일 업로드, 외부 API 호출이 검증되는가
- 개인정보, 위치 정보, 신고 데이터가 과하게 노출되지 않는가
- 운영 환경변수와 secret이 안전하게 다뤄지는가

문서에 남길 것:

- 보안 관점에서 본 악용 시나리오
- 반드시 막아야 할 취약점
- 구현 전 필요한 제약
- 보안 방향 결정

### DX 리뷰

사용 skill: `plan-devex-review`

개발자용 API, 스크립트, 문서, 환경 설정, 배포 플로우를 바꾸는 경우에만 실행한다.

문서에 남길 것:

- 개발자 경험에서 막히는 지점
- 문서나 명령어 개선점
- 유지할 로컬 개발 흐름
- DX 방향 결정

## 리뷰 결과 정리 형식

각 리뷰는 다음 형식으로 정리한다.

```markdown
## 리뷰 결과

### CEO 리뷰

- 생각: ...
- 우려: ...
- 제안: ...
- 결정: ...

### 디자이너 리뷰

- 생각: ...
- 우려: ...
- 제안: ...
- 결정: ...

### 개발자 리뷰

- 생각: ...
- 우려: ...
- 제안: ...
- 결정: ...

### 보안 이슈 리뷰

- 생각: ...
- 우려: ...
- 제안: ...
- 결정: ...

## 최종 정리된 방향

- 이번 작업에서 할 것: ...
- 이번 작업에서 하지 않을 것: ...
- 선택한 구현 방법: ...
- 선택 이유: ...
- 구현 순서: ...
- 검증 방법: ...
```

## 구현 시작 조건

Codex는 다음 조건을 만족한 뒤 구현을 시작한다.

- 하위 태스크가 정리되어 있다.
- 구현 후보와 선택 이유가 적혀 있다.
- 필요한 리뷰 관점의 생각, 우려, 제안, 결정이 남아 있다.
- 최종 정리된 방향이 하나로 합쳐져 있다.
- 테스트와 검증 방법이 정해져 있다.

새로운 사용자 메시지가 기존 방향을 바꾸면, 구현보다 먼저 기획안과 리뷰 결과를 갱신한다.
