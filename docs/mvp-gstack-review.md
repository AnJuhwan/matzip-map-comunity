# MVP GStack Review

작성일: 2026-05-16

## 요약

맛잘알 동네지도 MVP는 네이버지도 중심의 맛집 커뮤니티다. 사용자는 로그인 화면 없이 익명 세션으로 맛집과 리뷰를 등록하고, 같은 기기에서는 본인 글을 수정하거나 삭제할 수 있다. 협찬 여부는 입력하지 않고, 리뷰 투명성은 가격대, 추천 메뉴, 좋았던 점, 아쉬운 점, 재방문 의사로 만든다.

## 현재 구현 범위

- Next.js 15 App Router 기반 단일 지도 경험
- Supabase Anonymous Sign-In 기반 익명 작성자 프로필
- Supabase RLS 기반 공개 읽기, 작성자 수정, 작성자 삭제
- 가게 등록, 주소 검색, 지도 핀 확인, 중복 후보 확인
- 카테고리, 태그, 사진 업로드, 리뷰, 신고 접수
- Supabase 또는 네이버지도 설정이 없을 때 개발용 fallback

## CEO 관점

가장 중요한 제품 가정은 "로그인 없는 기록 경험이 맛집 제보 수를 늘린다"이다. 초기 MVP에서는 회원 기능보다 첫 등록까지의 마찰을 낮추는 편이 맞다. 협찬 여부를 빼는 결정도 현재 단계에서는 좋다. 사용자가 부담 없이 솔직한 리뷰를 쓰는 것이 핵심이고, 협찬 필드는 오히려 서비스가 광고 검증 서비스처럼 보이게 만들 수 있다.

다음으로 봐야 할 지표는 맛집 등록 완료율, 첫 리뷰 작성률, 중복 후보를 보고도 등록을 계속하는 비율이다. 지도 앱은 빈 화면이 치명적이므로, 운영 초반에는 샘플 또는 운영자가 넣은 seed 데이터 전략이 필요하다.

## 디자이너 관점

첫 화면이 랜딩 페이지가 아니라 지도와 리스트인 점은 목적에 맞다. 사용자는 "무슨 서비스인지"보다 "내 주변에 뭐가 있는지"를 먼저 보고 싶어 한다. 우측 패널은 등록, 검색, 카테고리, 닉네임, 목록이 한 흐름에 있어 MVP에는 충분하다.

다만 빈 상태는 더 다듬을 필요가 있다. Supabase에 데이터가 없는 실제 운영 첫날에는 `0곳`만 보이므로, "첫 맛집 등록"으로 바로 이어지는 빈 상태 CTA가 필요하다. 모바일에서는 지도와 리스트의 전환 방식도 다음 단계에서 탭 또는 하단 시트로 개선하는 것이 좋다.

## 개발자 관점

데이터 흐름은 단순하다.

```text
브라우저 진입
  -> Supabase 익명 세션 생성
  -> anonymous_profiles 조회 또는 생성
  -> places/reviews 공개 데이터 조회
  -> 지도와 패널 렌더링
  -> 작성/수정/삭제는 owner_id와 auth.uid()로 제한
```

RLS를 기본으로 켠 것은 맞다. 공개 읽기는 `status = 'public'`로 제한되고, 작성자 수정은 `owner_id = auth.uid()`로 제한된다. 이 구조는 로그인 없는 UX와 최소 권한 원칙을 같이 만족한다.

주의할 점은 Supabase 설정이다. 사용자 맛집/리뷰 데이터는 브라우저 저장소에 저장하지 않으므로, Supabase 설정이 빠졌을 때는 명확한 설정 오류가 보여야 한다.

## 사용자 관점

좋은 첫 경험은 "닉네임이 이미 만들어져 있고, 주소 검색 후 바로 저장된다"이다. 직접 로그인하지 않아도 내가 쓴 글을 다시 고칠 수 있다는 점은 설명이 짧게 필요하다.

리뷰 입력 항목은 적절하다. 특히 좋았던 점과 아쉬운 점을 모두 요구하는 방식이 별점보다 더 투명하다. 다만 아쉬운 점이 필수라서 좋은 경험만 남기려는 사용자는 멈출 수 있다. 운영 데이터가 쌓이면 필수 여부를 다시 판단한다.

## 리뷰어 관점

현재 PR에서 확인해야 할 핵심 리스크는 네 가지다.

- Supabase Anonymous Sign-In이 꺼져 있으면 앱이 초기화에 실패한다. 브라우저 저장소 fallback은 사용하지 않는다.
- `supabase/schema.sql` 또는 마이그레이션을 실행하지 않으면 테이블/컬럼 오류가 발생한다. README와 운영 문서에 명시해야 한다.
- 신고는 접수만 있고 관리자 처리 UI는 없다. MVP에서는 허용하되, 운영 전에 관리자 숨김 처리 루틴이 필요하다.
- Storage upload는 사용자 폴더 insert만 허용한다. 교체 업로드가 필요해지면 select/update policy를 추가해야 한다.
