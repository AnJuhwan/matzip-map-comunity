# 상세 리뷰 리스트와 작성 모달 계획

작성일: 2026-05-18

Notion 계획: https://www.notion.so/364f1beebaaf815d8655dfd9ae43add2

## 배경과 목표

상세 페이지에서 리뷰 작성 폼이 항상 노출되어 있어 사용자는 리뷰 목록을 먼저 보기 어렵다. 목표는 상세 페이지에 리뷰 카드 리스트를 우선 노출하고, `리뷰쓰기` 버튼을 눌렀을 때 모달에서 작성/수정하도록 바꾸는 것이다. 모달이 열린 동안 배경 스크롤을 잠그고, 닫을 때 사용자가 보던 스크롤 위치를 유지한다. 리뷰가 많아질 수 있으므로 리뷰 목록에는 가상 스크롤을 적용한다.

## 범위와 제외 범위

- 범위: 저장된 상세 페이지와 네이버 후보 상세 페이지의 리뷰 작성/수정 모달, 배경 스크롤 잠금/복원, 리뷰 카드 리스트, 가상 스크롤, 관련 테스트
- 제외 범위: 리뷰 데이터 모델 변경, Supabase 스키마 변경, 리뷰 정렬/필터 기능 추가, 새 디자인 시스템 도입

## 하위 태스크

- 상세 페이지 리뷰 작성 버튼
  - 수정 영역: `src/widgets/place-detail`
  - 완료 조건: 리뷰 폼이 기본 화면에 노출되지 않고 `리뷰쓰기` 버튼으로 모달을 연다.
  - 검증: E2E
- 리뷰 작성/수정 모달
  - 수정 영역: `src/widgets/place-detail`
  - 완료 조건: 모달이 모바일/데스크톱 viewport 안에 보이고 닫기/저장 후 닫힘이 동작한다.
  - 검증: E2E 및 수동 확인
- 배경 스크롤 잠금/복원
  - 수정 영역: `src/widgets/place-detail`
  - 완료 조건: 모달 열린 동안 body scroll이 잠기고 닫으면 기존 scrollY가 유지된다.
  - 검증: E2E
- 리뷰 카드 및 가상 스크롤
  - 수정 영역: `src/widgets/matzip-community/ui`
  - 완료 조건: 많은 리뷰에서도 렌더링된 카드 수가 제한되고 스크롤 컨테이너로 탐색 가능하다.
  - 검증: Vitest 또는 E2E
- 후보 상세 첫 리뷰 흐름 유지
  - 수정 영역: `src/widgets/place-detail`
  - 완료 조건: 네이버 후보도 버튼으로 모달을 열고 첫 리뷰 저장 후 saved detail로 이동한다.
  - 검증: E2E

## 구현 후보

1. 폼을 상세 페이지 하단에 접었다 펼치는 accordion으로 유지한다.
   - 장점: 구현 범위가 작다.
   - 단점: 사용자 요청인 모달과 배경 스크롤 잠금 요구를 충족하지 못한다.
2. 상세 페이지에서 모달 상태를 관리하고 기존 `ReviewForm`을 모달 안에 재사용한다.
   - 장점: 데이터 저장 흐름을 유지하고 변경 범위가 명확하다.
   - 단점: scroll lock과 focus/keyboard 처리를 별도 구현해야 한다.
3. 전역 modal provider를 새로 만든다.
   - 장점: 이후 공용 모달 확장이 쉽다.
   - 단점: 현재 요청 범위를 넘는 추상화다.

## 선택한 방법

방법 2를 선택한다. 기존 `ReviewForm`과 저장 로직을 재사용하면서 상세 페이지의 표시 구조만 바꾸면 요구사항을 가장 작게 만족한다. 가상 스크롤은 고정 추정 높이 기반으로 구현해 라이브러리 추가 없이 테스트 가능하게 만든다.

## 영향

- 데이터: 변경 없음
- API: 변경 없음
- UI: 상세 페이지의 리뷰 작성/수정 진입점이 버튼과 모달로 바뀐다.
- 상태 관리: 상세 페이지에 모달 open/editingReview 상태와 body scroll lock effect가 추가된다.
- 권한/보안: 기존 owner check, report/delete 흐름 유지

## 리뷰 결과

### CEO 리뷰

- 생각: 리뷰 목록을 먼저 보게 하는 것은 상세 페이지의 핵심 가치에 맞다.
- 우려: 모달과 가상 스크롤을 동시에 크게 만들면 범위가 커질 수 있다.
- 결정: 정렬/필터는 제외하고 작성 진입점과 목록 성능만 처리한다.

### 디자이너 리뷰

- 생각: 상세 정보 다음에 리뷰 리스트와 명확한 `리뷰쓰기` 버튼이 있어야 한다.
- 우려: 모바일에서 모달 높이가 길어져 닫기 버튼이나 저장 버튼이 가려질 수 있다.
- 결정: 모달 내부만 스크롤되게 하고 overlay/body는 잠근다.

### 개발자 리뷰

- 생각: 기존 `ReviewForm`을 재사용하고 E2E로 스크롤 잠금/복원을 검증하는 구조가 안전하다.
- 우려: 가상 스크롤 item 높이가 실제 카드 높이와 크게 다르면 스크롤 위치가 어색할 수 있다.
- 결정: 카드 예상 높이를 보수적으로 잡고 overscan을 둔다.

### 보안 이슈 리뷰

- 생각: 인증/권한/저장 API 변경은 없다.
- 우려: 모달 닫힘 중 저장 중복 제출이나 배경 조작이 가능하면 UX 문제가 생긴다.
- 결정: 기존 disabled submit을 유지하고 overlay는 modal role로 격리한다.

## 테스트와 검증

- 실패 E2E 추가: 상세 페이지에서 `리뷰쓰기` 버튼으로 모달 열기, 배경 스크롤 잠금, 닫은 뒤 scrollY 유지
- 후보 상세 E2E 업데이트: 첫 리뷰 작성도 모달에서 수행
- Vitest 추가/수정: 가상 스크롤 계산 또는 UI render 제한 검증
- 전체 검증: `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`, `npm run test:e2e`
