# PR 컨벤션

자동 PR 리뷰의 관점, 코드 링크, inline comment 기준은
[자동 PR 리뷰 하네스](pr-automated-review-harness.md)를 따른다.

이 프로젝트의 Pull Request는 항상 한국어로 작성한다. PR은 코드 변경의 의도와 검증 결과를 사람이 빠르게 판단하는 문서이므로, 팀의 기본 업무 언어에 맞춰 한국어를 우선한다.

## 언어

- PR 제목은 한국어로 작성한다.
- PR 본문은 한국어로 작성한다.
- PR 리뷰 요약, 코멘트 답변, 후속 설명도 한국어로 작성한다.
- 영어를 그대로 쓰는 항목은 브랜치 이름, 커밋 메시지, 명령어, 파일 경로, 코드 식별자, 외부 서비스 고유명사로 제한한다.
- 외부 도구가 영어 템플릿을 생성해도 PR에 올리기 전에 한국어로 바꾼다.

## 제목

제목은 아래 형식을 사용한다.

```text
[codex] <한국어 요약>
```

예시:

```text
[codex] 코드 컨벤션 구조 정리
[codex] 네이버 지역 검색 안정화
[codex] 리뷰 작성 흐름 검증 추가
```

## 본문

본문은 최소한 아래 내용을 한국어로 포함한다.

- 무엇을 바꿨는지
- 왜 바꿨는지
- 사용자나 개발자에게 어떤 영향이 있는지
- 어떤 검증을 했는지
- 리뷰에서 확인한 남은 리스크가 있는지

권장 템플릿:

```markdown
## 변경 내용

- ...

## 이유

...

## 영향

...

## 검증

- `npm run lint`
- `npm run typecheck`
- `npm test`

## 리뷰

...
```

## 예외

GitHub가 자동으로 보여주는 commit hash, branch name, check name, file path, command output은 번역하지 않는다. 다만 사람이 작성하는 설명 문장은 한국어로 덧붙인다.
